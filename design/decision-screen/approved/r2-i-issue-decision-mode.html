(i) Issue decision mode · what you see

  • Opening any issue with an open decision for the viewer enters this mode. Header chip: Decision mode. One button, Show all comments, leaves it.
  • Visible: title, description, status summary, sidebar, the decision thread with its 3 newest messages (Show 4 earlier expands), and the full decision card.
  • Collapsed, each openable in place: other comments, activity, sub-issues, linked PRs. No content is deleted.
  • It is a filter on the current comment list. It does not wait for CHE-5452.
  • Floating card hidden while the full card is on screen. Dashed note is annotation, not UI.

Option text (Markdown)

Options render bold, italic, code, lists and links. Tables, charts, Mermaid, HTML, images and headings are not rendered; they show as plain text. Card above: A has bold and a link, B has code and italic, C has a list.

Components, tokens, i18n

  • packages/views/issues/components/issue-detail.tsx gets a decisionMode filter over the existing comment list; card stays decision-request-card.tsx.
  • Markdown: the existing Markdown view with a restricted allow-list (decision-answer-content.tsx).
  • Tokens: --info-bg (mode chip), --surface-border, --brand (status summary rule).
  • Keys: decisions:mode.label, mode.showAll, mode.showEarlier (count), mode.collapsed.*, mode.progress (1/3). 6-locale parity.
  • Phone: properties fold into one row; collapsed rows are 44 px tall.
  • Focus: 2 px outline, 2 px offset, token --info, on every control; keyboard order follows reading order.
