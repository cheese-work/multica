B · Approve or Reject, or just talk. One composer, one button that names what happens.

Two choices only: Approve and Reject. Pick one, or pick neither (tap the chosen one again to clear it). Nothing is chosen when the card opens, so Enter can never approve by accident. The one composer is always there. The one big button always names the result: Discuss more with no choice, Approve with passkey or Confirm approval on Approve, Confirm Reject on Reject. The server's requiresPasskey flag on the action picks between the two Approve labels. Batches are opened on purpose by the agent, so the card is exact.

DevX · config action

The server derives the diff from RequiresPreview (live vs after). Nobody hand-writes a summary. A registry test fails for any config action with no diff renderer. Config actions set requiresPasskey: true, so their Approve button reads “Approve with passkey”.

registerConfigAction({ id: 'workflow.steps.set', requiresPreview: true, requiresPasskey: true, diff: fieldDiff({ by: 'step.key', fields: ['handler', 'status'] }) }) // text fields use textDiff; none → test fails $ go test -run TestEveryPreviewActionHasDiffRenderer FAIL every RequiresPreview action has a diff renderer agent.instructions.set: no renderer (add fieldDiff or textDiff)

DevX · what a person adding an action type writes

Every action registers a human template, a passkey flag and fixtures. A missing template fails the test, so no action ships without a plain card. This direction adds one CTA rule: the label comes from the choice and the flag; only a chosen Approve can start a passkey.

registerAction({ id: 'issue.run_budget.top_up', version: 1, requiresPasskey: true, // false → button reads "Confirm approval" human: { title: (p) => `Reopen ${p.issue.key}`, summary: (p) => `${p.issue.key} stopped at its run limit (${p.used} of ${p.limit}).`, change: (p) => ['Runs used', `${p.used} of ${p.limit}`, `0 of ${p.limit}`], ifIgnored: 'The issue stays paused.', batchable: true, }, fixtures: [topUpOpen, topUpOverLimit] }) $ pnpm test actions FAIL every action has a human template + passkey flag + ≥1 fixture issue.run_budget.pause_all: missing `human` (add title, summary, change)
