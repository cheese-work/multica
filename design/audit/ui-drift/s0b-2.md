## Method and limits

- Each file is mapped to a proposed pattern `id`. Each drift item has a sibling flag, a reference flag and a kind (copy, component or layout).
- Sibling = another surface in this fork that already solves the same job. "Reference would have pointed" = a pattern reference that names the sibling would have led the author to it.
- Reference screens: issue detail page, inbox and settings. The comparison is by code only (components, tokens and locale keys). No rendered frame was compared. This batch has no screenshots.
- Drift ids D1 to D54 are local to this file. S0b-1 ids are written as "S0b-1 D3".
- Pattern ids are proposals for `design/patterns.yml`. None exists yet.
- Upstream comparison: all 40 files are absent from upstream `250ecacf4a` (`git cat-file -e 250ecacf4a:packages/views/<file>` fails for each), so they are fork-only. This differs from S0b-1, where `git ls-tree` returned nothing. No upstream sibling was compared.
- Read depth: 32 files were read in full. 8 files were read by targeted `grep` of elements, class strings, formatters and retry code plus line ranges: `chat-search.tsx`, `chat-session-stats-dialog.tsx`, `config-change-viewer.tsx`, `predecessor-dms.tsx`, `deferred-content-editor.tsx`, `decision-artifacts.tsx`, `needs-you-list.tsx`, `decision-request-card.tsx`. Drift in logic or in markup that the grep did not match can be missed in those 8.
- Raw-element marker: a file marked (raw) in the batch plan has `screenshot: S4b` in the file map. The screenshot work moves to S4b. No frame, no link and no upload were made. Nothing is fabricated.

- `hierarchy-dialog.tsx`: the SVG overview colours `fill-info` and `fill-warning` repeat the status colour map of D6. Module-level mutable `focusHeadingOnMount` in `hierarchy-minimap.tsx` is logic, not UI.
