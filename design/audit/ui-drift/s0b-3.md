Issue: CHE-5449. Parent: CHE-5424 (S0b). Plan: CHE-5420 rev 19. Batch plan: old batches 6, 7, 8 and 9 (`chat/components/use-archived-send.tsx` to `agents/components/tabs/agent-mcp-tab.tsx`).
Audit date: 13 Nov 2026 (ICT). Scope: read-only audit of 32 fork-only files under `packages/views/`. No code changed.

## Method and limits

- Each file is mapped to a proposed pattern `id`, or a drift item is recorded. Pattern ids reuse `s0b-1.md` ids where they fit (`ict-timestamp`, `inline-retry`, `status-pill`, `inline-notice`, `property-picker`, `description-disclosure`). Other ids are new proposals for `design/patterns.yml`. None exists yet.
- Sibling = another surface in this fork that already solves the same job. "Reference would have pointed" = a pattern reference that names the sibling would have led the author to a fix. It is marked "no" when the sibling is another unextracted copy of the same code. In that case the author copied the sibling on purpose, and only a shared component would have prevented the drift.
- Reference screens: issue detail page, inbox, settings. The comparison is by code only (components and locale keys). No rendered frame was compared.
- Upstream comparison: not done. The fork tree is the only evidence.
- Depth of reading. 25 files were read in full (comments, blank lines and imports stripped). 7 files were not read line by line, because they are long: `dingtalk-tab.tsx` (1159 lines), `lark-tab.tsx` (991), `create-agent-dialog.tsx` (670), `wecom-tab.tsx` (635), `slack-tab.tsx` (602), `telegram-tab.tsx` (557), `wecom-scan-install-dialog.tsx` (300). For these 7 the evidence is a structural scan (counts of raw `<button>`, raw colours, `Alert`, date calls, `role="alert"`), plus reads of the line ranges that the scan flagged. A drift item in these files is listed only if the flagged lines were read. A drift not flagged by the scan may be missed. Treat the integration-tab results as a lower bound.
- Time per file is not a true per-file time. Markers come from a `date` call in each read command. One command read 1 to 7 files. See Calibration.

Markers come from a `date +%H:%M:%S` call inside each read command, so a marker shows when the command ran, not how long a file took. One command read 1 to 7 files. The elapsed time of a group is the gap from the previous marker, so it also includes the time to think about the previous output. The per-file figure is the group time divided by the number of files, rounded. It is not a measured per-file time.
