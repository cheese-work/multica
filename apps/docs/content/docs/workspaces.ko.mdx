워크스페이스는 Multica의 최상위 경계입니다. 멤버, 태스크, 프로젝트, 에이전트, 스킬, 실행 기록은 모두 하나의 워크스페이스에 속하며, 다른 워크스페이스와는 서로 공유되지 않습니다.

## 워크스페이스의 구성

| 범주 | 내용 |
|---|---|
| **작업** | 태스크, 프로젝트, 댓글, 첨부 파일, 실행 기록 |
| **팀** | 멤버, 역할, 초대 |
| **에이전트** | 에이전트 설정, 스킬, 런타임, 자동화 |
| **공유 설정** | 컨텍스트, 라벨, [사용자 지정 속성](/issues#사용자-지정-속성), 연동 |

**컨텍스트**는 워크스페이스의 모든 에이전트에게 제공됩니다. 팀 배경, 제품 규칙, 장기적으로 적용되는 요구 사항을 작성하기에 적합합니다. 일회성 요구 사항은 해당 태스크에 작성하세요.

## 워크스페이스 만들기

만들 때 세 항목을 입력합니다.

- **이름**: 멤버에게 표시되며 나중에 변경할 수 있습니다.
- **워크스페이스 URL**: 주소에 들어가는 slug입니다. 예를 들어 `multica.ai/my-team`의 `my-team`입니다. 소문자, 숫자, 하이픈만 사용할 수 있고 기존 워크스페이스 또는 예약된 주소와 중복될 수 없으며 만든 뒤에는 변경할 수 없습니다.
- **태스크 접두사**: 워크스페이스 URL에서 자동으로 채워지며 만들기 전에 바꿀 수 있습니다. 접두사가 `MUL`이면 태스크 번호는 `MUL-1`, `MUL-2`처럼 표시되며 워크스페이스 안에서 독립적으로 증가합니다. 대문자와 숫자만, 최대 10자이며 나중에 설정에서도 바꿀 수 있습니다.

만든 사람은 자동으로 `owner`가 됩니다.

## 설정 변경

`owner`와 `admin`은 이름, 아이콘, 설명, 컨텍스트, 태스크 접두사를 변경할 수 있습니다. `member`는 보기만 할 수 있습니다.

![워크스페이스 설정: 이름, 컨텍스트, slug, 태스크 접두사, 위험 구역](/images/docs/workspace-settings.webp)

<Callout type="warning">
태스크 접두사를 변경하면 모든 태스크가 즉시 새 번호를 사용합니다(`MUL-5`가 `NEW-5`로 변경). 하지만 PR, 브랜치 이름, 채팅 기록의 이전 번호는 업데이트되지 않습니다.
</Callout>

### 요청 가드

워크스페이스 설정 `ask_guard_mode`는 에이전트 작업이 결정 요청을 열지 않고 사람에게 작업을 요구할 때의 동작을 정합니다.

| 값 | 동작 |
| --- | --- |
| `off` (기본값) | 가드는 아무 일도 하지 않습니다. |
| `warn` | 가드가 이벤트와 메트릭을 기록합니다. 작업은 그대로 진행됩니다. |
| `block` | 가드가 먼저 이벤트를 기록한 뒤 `422`로 작업을 거부합니다. 복구 작업이 되는 것은 `block` 이벤트뿐입니다. |

각 이벤트는 생성 당시의 모드를 유지하므로 `warn`에서 `block`으로 바꿔도 이전 이벤트가 복구 작업이 되지 않습니다. 이벤트를 기록할 수 없으면 작업은 `503`과 `Retry-After` 헤더로 실패하며 아무것도 기록되지 않습니다.

가드는 에이전트가 사람이 트리거할 수 있는 웨이크업을 등록하는 작업도 다룹니다. `--decision`으로 묶거나, `--purpose observe`로 표시하거나, 에이전트로만 제한하세요. [웨이크업](/cli#wakeups)을 참고하세요.

### 위임된 거버넌스 대상 쓰기

워크스페이스 설정 `delegated_governed_writes`는 어떤 에이전트가 거버넌스 대상 필드에 쓸 수 있는지, 그리고 각 쓰기에 사람의 결정이 여전히 필요한지를 정합니다. 워크스페이스 설정의 **위임된 거버넌스 대상 쓰기**에 있습니다.

- **편집 가능한 사람:** `owner`와 `admin`. `member`는 같은 표를 읽기 전용으로 보며, 잠금 안내가 표시되고 편집 버튼은 없습니다.
- **허용된 에이전트:** 쓸 수 있는 에이전트. 보관된 에이전트는 추가할 수 없습니다.
- **허용된 필드:** `workflow.steps`, `workflow.instructions`, `workspace.context`, `squad.instructions`, `agent.instructions`, `project.description`, `workflow.budget`, `issue.workflow` 중에서 고릅니다. 선택하지 않은 필드는 모든 에이전트에게 읽기 전용으로 남습니다.
- **사람의 결정 필요:** 기본값은 켜짐입니다. 켜져 있으면 허용된 에이전트는 쓰는 대신 결정 요청을 엽니다. 끄면 허용된 에이전트가 직접 쓰므로, 저장하기 전에 확인을 요구합니다.

저장에 실패해도 저장되지 않은 편집은 유지되므로 입력한 내용이 사라지지 않습니다.

## 전환 및 나가기

하나의 계정으로 여러 워크스페이스에 참여할 수 있습니다. 워크스페이스를 전환하면 지금 보고 있는 범위만 바뀌고 데이터는 옮겨지지 않습니다.

워크스페이스를 나가면 다시 참여하려면 초대를 새로 수락해야 합니다. 나갈 때는 본인이 소유한 런타임도 비활성화되고, 해당 런타임에 연결된 에이전트는 보관 처리되며, 완료되지 않은 실행은 취소됩니다.

마지막 `owner`는 워크스페이스를 나갈 수 없습니다. 먼저 다른 멤버를 `owner`로 승격해야 합니다.

## 워크스페이스 삭제

워크스페이스는 `owner`만 삭제할 수 있습니다. 삭제하면 그 안의 모든 작업, 멤버, 에이전트 설정, 실행 기록이 영구적으로 제거되며 복구할 수 없습니다. 잠시 참여하지 않을 뿐이라면 나가기만 해도 충분합니다.
