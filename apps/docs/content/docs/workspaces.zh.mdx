工作区是 Multica 的最上层边界。成员、任务、项目、智能体、skill 和执行记录都属于某一个工作区，不同工作区之间互不相通。

## 工作区的组成

| 类别 | 内容 |
|---|---|
| **工作** | 任务、项目、评论、附件、执行记录 |
| **团队** | 成员、角色、邀请 |
| **智能体** | 智能体配置、skill、运行时、自动化 |
| **共享设置** | 上下文、标签、[自定义属性](/issues#自定义属性)、集成 |

**上下文**会提供给工作区中的每个智能体，适合写团队背景、产品约定和长期有效的要求。一次性的运行要求写在对应的任务里。

## 创建工作区

创建时要填三项：

- **名称**：展示给成员，之后可以修改。
- **工作区 URL**：地址中的 slug，例如 `multica.ai/my-team` 里的 `my-team`。只能用小写字母、数字和连字符，不能与已有工作区或保留地址重复，创建后不可修改。
- **任务前缀**：根据工作区 URL 自动填好，创建前可以改。前缀为 `MUL` 时，任务编号显示为 `MUL-1`、`MUL-2`，在工作区内独立递增。只能用大写字母和数字，最多 10 位，之后也可以在设置里修改。

创建者自动成为 `owner`。

## 修改设置

`owner` 和 `admin` 可以修改名称、图标、描述、上下文和任务前缀；`member` 只能查看。

![工作区设置：名称、上下文、slug、任务前缀与危险区](/images/docs/workspace-settings.webp)

<Callout type="warning">
修改任务前缀后，所有任务立即换用新编号（`MUL-5` 变为 `NEW-5`），但 PR、分支名和聊天记录里的旧编号不会更新。
</Callout>

### 请求守卫

工作区设置 `ask_guard_mode` 决定当智能体的操作未创建决策请求就要求人去处理时的行为。

| 取值 | 效果 |
| --- | --- |
| `off`（默认） | 守卫不做任何事。 |
| `warn` | 守卫记录事件和指标，操作继续执行。 |
| `block` | 守卫先记录事件，再以 `422` 拒绝该操作。只有 `block` 事件会成为恢复工作。 |

每个事件保留创建时的模式，因此从 `warn` 切换到 `block` 不会让之前的事件变成恢复工作。如果事件无法写入，操作会以 `503` 和 `Retry-After` 头失败，且不会写入任何内容。

当产生 `block` 事件的运行结束后，服务器会向请求所指名的那一个人发送自动恢复通知：在一个事务中写入一条私信、一条议题评论和一个收件箱条目。通知引用已存储的请求并链接到议题，没有选项、建议或批准，因此永远不是决策请求。只有在存储的来源包含请求文本、恰好指名一位成员、且该成员仍在工作区时才会发送；否则该事件等待修复。在通知的评论线程中回复会将其标记为 `answered`。已离开工作区的成员无法再阅读或回复该通知。

守卫也覆盖智能体注册人可触发的唤醒。用 `--decision` 绑定、标记 `--purpose observe`，或限定为仅智能体；见[唤醒](/cli#wakeups)。

### 委托的受管写入

工作区设置 `delegated_governed_writes` 决定哪些智能体可以写入受管字段，以及每次写入是否仍需要人来决定。它位于工作区设置的 **委托的受管写入** 下。

- **谁可以编辑：** `owner` 和 `admin`。`member` 以只读方式查看同一张表，会看到锁定提示，没有编辑按钮。
- **允许的智能体：** 可以写入的智能体。已归档的智能体不能添加。
- **允许的字段：** 可从 `workflow.steps`、`workflow.instructions`、`workspace.context`、`squad.instructions`、`agent.instructions`、`project.description`、`workflow.budget`、`issue.workflow` 中选择。未勾选的字段对所有智能体保持只读。
- **需要人工决定：** 默认开启。开启时，被允许的智能体会发起决策请求，而不是直接写入。关闭后，被允许的智能体直接写入，因此保存前会先要求你确认。

保存失败时，未保存的编辑会保留，你输入的内容不会丢失。

## 切换和离开

一个账号可以加入多个工作区。切换工作区只换了你正在看的范围，数据不会移动。

离开工作区后，需要重新接受邀请才能回来。离开会同时停用你拥有的运行时、归档绑定在其上的智能体，并取消它们未结束的运行。

最后一名 `owner` 不能离开，需要先把另一位成员提升为 `owner`。

## 删除工作区

只有 `owner` 可以删除工作区。删除会永久移除其中的全部工作、成员、智能体配置和执行记录，无法恢复。只是暂时不参与的话，离开就够了。
