워크플로는 프로젝트의 태스크가 거칠 단계, 각 단계를 처리할 사람, 해야 할 일을 정합니다.

예를 들어 개발 작업을 다음과 같이 구성할 수 있습니다.

| 단계 | 담당 | 할 일 |
|---|---|---|
| 개발 | 개발 에이전트 | 변경을 구현하고 리뷰를 준비합니다. |
| 리뷰 | 리뷰 에이전트 | 결과를 확인한 뒤 QA로 넘기거나 수정을 위해 돌려보냅니다. |
| QA | 팀 멤버 | 결과를 직접 사용해 보고 완료해도 될지 판단합니다. |

태스크를 리뷰 단계로 옮기면 리뷰 에이전트가 이어받습니다. 설명, 논의, 이전 결과는 같은 태스크에 남아 다음 담당자가 이어서 일할 수 있습니다.

**개발 딜리버리** 템플릿이 바로 이 구성입니다. 워크플로를 선택하지 않은 프로젝트는 **Default**를 사용합니다. 모든 상태를 쓸 수 있고 자동 인계도 없어 이전과 똑같이 동작합니다.

## 워크플로 만들기

워크스페이스의 `owner` 또는 `admin`이 웹이나 데스크톱 앱에서 만들 수 있습니다.

<Steps>
<Step>

**설정 → 워크플로**에서 **새 워크플로**를 선택합니다. 빈 상태로 시작하거나 **개발 딜리버리**, **콘텐츠 제작**, **커뮤니티 운영** 템플릿을 사용할 수 있습니다.

</Step>
<Step>

이름을 정하고 필요한 상태 열을 선택합니다. 가운데 열은 드래그해 순서를 바꿉니다.

</Step>
<Step>

열을 선택하고 태스크가 들어올 때 **넘기지 않음**, **에이전트에게 넘기기**, **멤버에게 넘기기** 중 하나를 정합니다. 멤버 목록에서 **프로젝트 리드**도 선택할 수 있습니다.

</Step>
<Step>

에이전트에게 넘긴다면 이 단계에서 할 일을 적고, **완료 후 이동**할 단계(지정하지 않으면 다음 열)와 **반려 시 되돌릴 단계**(받은 작업이 기준에 못 미쳐 다시 해야 할 때 사용)를 선택합니다. 외부 사정으로 진행할 수 없을 때는 되돌리기 대신 **Blocked**를 씁니다.

</Step>
<Step>

에이전트가 받을 설명을 미리 보고 저장합니다.

</Step>
</Steps>

새 상태를 추가했다면 워크플로를 먼저 저장한 뒤 그 상태의 인계를 설정합니다.

인계하지 않으면 담당자는 그대로입니다. 멤버에게 인계하면 담당자만 바뀌며 에이전트가 실행되지는 않습니다. 에이전트에게 넘기면 해당 단계를 시작하도록 요청합니다. 호출 권한이 있어야 하며, 실제 실행에는 에이전트의 컴퓨터가 온라인이어야 합니다.

`keep_other_assignee: true`인 단계는 현재 담당자가 의도적으로 선택된 경우(이 단계의 담당자도, 태스크가 떠나는 단계의 담당자도 아닌 경우) 인계를 건너뜁니다. 그 담당자가 태스크를 계속 맡고, 담당자가 에이전트이면 이 단계의 실행이 시작됩니다. 기본값은 꺼짐이며 API나 CLI로 설정합니다. 임시 기능이며 태스크별 워크플로(CHE-5024)로 대체됩니다.

## 프로젝트에서 사용하기

프로젝트를 열고 **워크플로** 속성에서 선택합니다. 워크스페이스의 `owner`, `admin`, 그리고 멤버인 프로젝트 리드가 변경할 수 있습니다.

확인 창에 현재 상태를 유지하는 태스크가 표시됩니다. 새 워크플로에 없는 상태를 사용하는 태스크는 이동할 곳을 선택합니다. 워크플로를 바꾸는 것만으로는 담당자 인계나 에이전트 실행이 일어나지 않습니다.

프로젝트 보드는 워크플로의 열을 따릅니다. 태스크의 상태 목록도 해당 단계만 제공하며, 누가 이어받는지 보여 줍니다. 다른 워크플로를 선택하지 않은 프로젝트는 **Default**를 사용하며, 나중에 다시 돌아갈 수 있습니다.

## 제목 유형으로 워크플로 고르기

워크스페이스 소유자나 관리자는 워크스페이스 설정에 `workflow_by_type`을 지정할 수 있습니다. 예: `{"design": "<워크플로 ID>", "plan": "<워크플로 ID>"}`. 제목이 `design(x): …`처럼 지정한 유형으로 시작하는 새 이슈는 프로젝트의 워크플로 대신 해당 워크플로를 따릅니다. `--workflow`(CLI)나 명시적 선택이 항상 우선합니다. 항목이 없는 유형이나 워크플로가 없어진 항목은 프로젝트의 워크플로를 유지합니다. `multica issue create`는 선택된 워크플로를 출력합니다. 제목에 지정한 유형이 있으면 생성 창이 선택될 워크플로의 상태와 인계를 보여 줍니다. 이 매핑은 워크스페이스 정책이라 에이전트를 포함한 모든 생성자에게 적용되며, 비대화형 호출자가 명시적 `--workflow`에서 받는 실행 예산 확인은 거치지 않습니다. 대소문자만 다른 키가 둘 이상이면 알파벳순으로 첫 번째가 우선합니다. 나중에 제목을 바꿔도 워크플로는 바뀌지 않습니다. 업데이트 응답에는 한 줄짜리 `workflow_hint`(`multica issue update`가 출력)가 들어 있어 옮기는 명령을 알려 줍니다.

## 다음 단계로 넘기기

태스크의 상태를 바꾸거나 카드를 다른 열로 드래그합니다. 인계가 있는 단계라면 받을 사람을 확인합니다. 에이전트라면 받을 설명도 확인할 수 있습니다.

<WorkflowDemo />

프로젝트에서 태스크를 만들었는데 그 상태에 인계가 설정되어 있으면, 담당자를 골랐더라도 태스크는 해당 단계의 담당자에게 바로 넘어갑니다. 에이전트라면 즉시 작업을 시작합니다. 생성 창에 "생성 후 ○○에게 인계됩니다"라고 표시됩니다. 아직 아무것도 시작하지 않으려면 Backlog에 만드세요.

이전 담당자가 에이전트이고 아직 실행 중이거나 시작을 기다리고 있다면, 확인 창에 그 실행을 중지하거나 취소하는 옵션이 추가되며 기본으로 선택되어 있습니다. 두 에이전트가 함께 작업하기를 원하는 경우가 아니면 그대로 두세요. 그 에이전트가 이미 게시한 댓글과 저장한 작업은 사라지지 않습니다.

**완료 후 이동**과 **반려 시 되돌릴 단계**는 에이전트에게 태스크를 다음에 어디로 옮길지 알려 줍니다. 실행이 끝났다고 태스크가 저절로 다음 단계로 넘어가지는 않으며, 해당 단계의 멤버나 에이전트가 상태를 바꿉니다. 에이전트가 태스크를 다음 단계로 옮길 때도 그 단계의 인계가 똑같이 일어납니다.

인계 내역과 설명은 태스크 타임라인에 남습니다. 프로젝트 보드의 워크플로 메뉴에서 전체 흐름을 볼 수 있습니다.

## 워크플로 조정하기

여러 프로젝트가 같은 워크플로를 사용할 수 있습니다. **설정 → 워크플로**에서 저장한 변경은 사용하는 모든 프로젝트에 적용됩니다. 한 프로젝트만 바꾸려면 워크플로를 복제하고 해당 프로젝트에서 사본을 선택합니다.

관리자는 프로젝트 보드에서 바로 인계를 설정할 수도 있습니다. 열 머리글에 마우스를 올리고 **넘기기…**를 클릭하거나, 이미 표시된 담당자를 클릭합니다. 다른 프로젝트와 공유하는 워크플로라면 **이 변경을 어디에 적용할까요?**라고 묻습니다. 현재 프로젝트에만 적용하면 그 프로젝트용으로 워크플로가 복제되고 다른 프로젝트는 바뀌지 않습니다.

열을 제거할 때 태스크가 남아 있다면 새 상태를 선택합니다. 나머지 태스크는 그대로이며 이 이동으로 에이전트가 시작되지는 않습니다. 워크플로 목록 아래 상태 라이브러리에서 이름과 색을 바꾸면 같은 상태를 쓰는 모든 곳에 반영됩니다.

워크플로 편집기의 **이슈당 최대 실행 횟수**로, 워크플로가 이슈를 차단하기 전에 이슈 하나가 시작할 수 있는 실행 횟수를 제한합니다(1~1000, 비워 두면 기본값 15). 변경에는 로그인된 웹 또는 데스크톱 세션이 필요하며, 이 칸을 건드리지 않는 저장은 어떤 클라이언트에서든 가능합니다. 옆의 **하위 PR 포함** 스위치는 PR 가드가 하위 이슈의 PR도 읽을지 정하며(기본값 켜짐) 같은 규칙을 따릅니다. 에이전트나 토큰은 두 필드를 직접 바꿀 수 없습니다. `budget_requires_decision` 이 반환되며, `multica config propose workflow.budget` 으로 변경을 제안하면 소유자가 패스키로 승인합니다. 에이전트나 토큰이 더 넓은 예산의 워크플로로 이슈를 만들거나 바꿀 때도 같은 제한이 적용됩니다(`budget_rebinding_requires_interactive`). 같은 결정으로 풀 수 있습니다. `multica issue create` 와 `multica issue update` 는 `--workflow <id> --decision-id <id>` 를 받습니다.

실행 예산이 있는 이슈의 사이드바에는 사용한 실행 횟수, 남은 횟수, 80 % 경고, **실행 예산을 모두 사용했습니다** 상태를 보여 주는 미터가 표시됩니다. **한도 올리기**와 **충전**은 워크스페이스 소유자에게 추가 실행 승인을 요청합니다. 소유자라면 그 자리에서 패스키로 승인하고, 아니면 소유자가 요청을 받습니다.

워크플로를 삭제하려면 먼저 사용 중인 프로젝트를 다른 워크플로로 전환하세요. 태스크는 현재 상태를 유지합니다.

**설정**에 **워크플로**가 없다면 이 워크스페이스에서는 아직 사용할 수 없습니다. 상태는 계속 **설정 → 태스크 상태**에서 관리합니다.
