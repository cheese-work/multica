Chat fits work that hasn't become a clear issue yet: sorting out ideas, checking on the workspace, discussing an approach, asking a question that doesn't belong to any issue, or having an agent finish a small task first.

Chat is a one-to-one conversation between you and an [agent](/agents), off the [issue](/issues) board. The whole conversation is **fully private**: nobody else in the [workspace](/workspaces), admins included, can see it.

A chat is **not bound to any issue**. The agent isn't watching your board, doesn't automatically receive an issue's description and comments, and won't turn the conversation into issues on its own. It can still use the Multica CLI to query workspaces, projects, issues, and skills within its permissions, and when you explicitly ask, it acts with your workspace access, for example to create an issue.

A chat can also carry background. Click **+** at the bottom left of the input and choose **Project context** to attach a [project](/projects) to the conversation; when the agent runs, it receives that project's description, repositories, and other resources.

## Start a conversation

<Steps>
<Step>

Open **Chat** in the sidebar.

</Step>
<Step>

Click new and pick an agent you have permission to run.

</Step>
<Step>

Type a message; you can also attach images or files.

</Step>
<Step>

After you send, Multica creates a run for the message, and the reply comes back to the current conversation.

</Step>
</Steps>

If the runtime is offline, the message waits until it comes back online. Once the agent is archived, or you lose permission to run it, you can't send new messages.

Before the first message, Chat shows up to three suggestions configured for the selected agent. Selecting one only fills the composer with its full prompt; nothing is sent, so you can edit it first. Agents without configured suggestions show general-purpose examples.

After the agent replies, it sometimes offers **Follow-up questions** below the reply. Clicking one sends it right away.

## Chat from any page

You don't have to leave the page you're on to chat. Workspace pages can open a chat in a floating window. The window and the **Chat** page share the same conversations, so you can pick up a chat from either one.

In a wide window, quick chat sits at the right end of the status bar along the bottom of the app:

- **Ask Multica** starts a new chat.
- A chat gets a chip in the bar while the agent is working on it, while it has a reply you haven't read, and once you've opened it in the floating window. A spinner on the chip means the agent is replying, and a colored dot means an unread reply; hover the chip to see the chat's title and state. Click a chip to open that chat, and click it again to close the window. Chips that don't fit go into a **+N** menu.
- To close a chip, hover it and click **×**. It comes back when the chat gets a new message or when you open the chat again.
- **Chat history**, the last button in the bar, lists your recent chats with the same running and unread marks. Pick one to open it, or click **All chats** to go to the **Chat** page.
- The window opens above the button or chip you clicked.

A narrow window has no status bar. Instead, a round chat button in the bottom-right corner opens the window. The button pulses gently while an agent is replying, and its tooltip says when a chat is running or has unread replies.

- Press `⌘J` (`Ctrl+J` on Windows and Linux) to open or close the floating window; opening it puts the cursor in the message input. The key works while you're typing in that input, too. You can rebind it under **Settings → Shortcuts**; see [Search, shortcuts, and preferences](/shortcuts).
- Press `⇧⌘J` (`Ctrl+Shift+J` on Windows and Linux) to start a new chat instead, the same as **Ask Multica**; `⌘J` reopens the chat you had open last. Press it again on the new chat to close the window.
- Drag the window's edges to resize it, or expand or minimize it.
- On the **Chat** page itself, quick chat doesn't appear in the status bar and the round button doesn't show. Neither `⌘J` nor `⇧⌘J` does anything there: the page already shows the same conversation.

If you don't want the floating window, turn off **Floating chat window** under **Settings → Preferences → Comments & chat**. Quick chat then leaves the status bar, the round button no longer appears, and Chat is reachable only from the sidebar. The switch applies to the current device only.

## Chat vs. issues

| Need | Better fit |
|---|---|
| Quick questions, exploring an approach, or private drafts | **Chat** |
| A clear assignee, status, priority, and deliverable | **Issue** |
| Letting teammates see the background and continue the discussion | **Issue** |
| A quick look at workspace information with no work record needed | **Chat** |

Direct chats created in Multica can be read only by their creator, not by other members or admins. Put conclusions the team needs to see into an issue, a project description, or a skill.

## Multi-turn context

A conversation tries to continue the original session in the AI coding tool, so later messages don't need to repeat earlier content. Multica stores the session ID and routes subsequent runs to a runtime that can access that session.

If the local session no longer exists, the context can't be continued, or the previous error shouldn't be reused, the runtime starts from a fresh session. The conversation's message history is kept either way.

## Watch and stop a run

While the agent runs, the UI shows the current phase and tool activity. Expand **View details** to inspect the run in full. Messages the agent writes between tool calls appear in the conversation as they are written, so you don't need to expand the details to read them.

To interrupt, click the stop button next to the input (shown while the input is empty). Content already returned to the conversation is kept.

If the agent hadn't produced anything yet, the message you just sent is taken back out of the conversation and returned to the input, attachments included, so you can edit and resend it. Stopping sometimes takes a moment to finish; refreshing the page or closing the window in the meantime doesn't lose the message, and it comes back to the input the next time you open that conversation. If the input already holds another draft, the message waits until you clear it.

## Send messages while a reply is in progress

You can keep typing while the agent is replying. **Send** adds a plain text message without a skill link to the current reply without stopping it, when the runtime supports steering. The agent reads it at its next safe boundary and continues the original task. Upgrade your daemon to enable this.

On web and desktop, **Add to current run** above your draft means your text will join the running reply. **Start after this run** means the message will be queued, for example when it has files or a skill link, or the current run doesn't support steering.

Messages with attachments or skill links, and messages sent before a reply starts or to a runtime without steering support, enter the queue. If guidance is not delivered before the reply ends, it automatically becomes a queued message; you do not need to resend it. If you stop while delivery is in progress, Chat waits for its result before queuing undelivered guidance. If the reply is retried automatically, guidance stays with the original request so both are processed together. When resuming the same session, guidance already delivered there is not sent again.

Queued messages appear above the input and run in order. You can remove them, use **⋯ → Edit queued message** to restore them to the input, or **⋯ → Clear all** to withdraw them. **Send now (stops current reply)** moves a queued message to the front and stops the current reply. It requires an active reply and permission to run the agent.

Steering applies to direct Chat sessions on updated web, desktop, and mobile clients. On mobile, queued messages appear at the end of the conversation; remove or edit them on web or desktop. Older clients and Slack and Lark channel conversations keep their existing queue behavior.

## Follow up later [#follow-up-later]

Ask the agent to report back when something happens, for example, "Tell me when this issue is ready for review" or "Remind me in two hours." It can create a wakeup that starts another run in this conversation when an issue reaches a status, sub-issues finish, a GitHub PR merges or closes, its checks finish, a run ends, or a member comments on an issue. It can also return at a set time or check periodically.

On web and desktop, a card under the reply records the follow-up. The strip above the input shows what the agent is waiting for and its deadline. Open the strip or the clock button in the conversation header to see **Wakeups**, including those that ended in the past 7 days. Use **Cancel wakeup** to stop waiting; if a report run fails or is cancelled, use **Retry** to request it again.

Conditions and periodic checks wait 24 hours by default, at most 7 days. If the deadline arrives first, the agent gets one final turn to report where things stand. One-time reminders can be scheduled up to 30 days ahead. A conversation can have at most 10 active wakeups. Archiving the conversation cancels its active wakeups; losing access to the agent or watched work can also end them.

For ongoing schedules such as a daily report, use an [autopilot](/autopilots). Agents manage follow-ups with [`chat wakeup`](/cli#chat-wakeups).

## Organize the conversation list

Conversations can be renamed, pinned, archived, and deleted:

- **Pin** keeps frequently used conversations at the top of the list;
- **Archive** moves a conversation to Archived and makes it read-only;
- **Unarchive** lets you send messages again;
- **Delete** permanently removes the conversation and its messages.

Open these from the **⋯** on a row (it shows when you hover the row or tab to it) or by right-clicking the row. With a row focused, press `U` to mark it unseen, `P` to pin, `E` to archive, and `R` to rename; the keys do nothing while you type in a field or hold `⌘`, `Ctrl`, or `Alt`.

To act on several conversations at once, press `X` on a focused row, choose **Select multiple**, or long-press a row on a phone. Tick rows, or tick a day header to select its whole group, then use the bar at the bottom: **Mark seen**, **Pin** and **Archive**. Each button follows your selection (for example **Unpin** when most selected rows are pinned), and its **▾** offers the opposite action with the number of conversations it applies to. Bulk delete does not exist.

If a conversation is bound to an external channel (such as Slack), archiving breaks the binding; unarchiving does not restore it — bind again.

The number of unread replies across your conversations shows as a badge on **Chat** in the app rail. In the desktop app, right-click **Chat** for **Mark all as read**.

<Callout type="warning">
Deleting a conversation cannot be undone and stops any runs in it that haven't finished. Archive instead when you just don't need it for now.
</Callout>

## Built-in slash commands

Type `/` at the start of the chat composer to run built-in Multica commands alongside agent skills:

| Command | Availability | Description |
|---|---|---|
| `/statistic` | Active DM | Show token usage and cost for the current DM (also matches `stats`, `statistics`, and `usage`). |
| `/archive` | Active DM | Archive the current DM without starting an agent turn. |
| `/pin` | Active DM | Pin or unpin the current DM. |
| `/unseen` | Active DM | Mark the current DM as unseen and leave it. The unread badge shows until you open the chat again (also matches `unread`). |
| `/unarchive` | Archived DM | Unarchive the current DM immediately without sending a message to the agent. |
| `/compact [focus]` | Active DM | Summarize the current DM and continue in a new one (runs the agent). |
| `/rename <title>` | Active DM | Rename the current DM without starting an agent turn. |
| `/fork [message]` | Active DM | Copy the current DM into a new one and optionally send a message there. |
| `/later [duration]` | Active DM | Snooze everything the current DM shows in "Needs you" (also matches `snooze`). The duration is a number plus `s`, `m`, `h` or `d`, from 1 second to 7 days; the default is 2 hours. Nothing is sent to the agent. |

Client commands (`/statistic`, `/archive`, `/pin`, `/unseen`, `/unarchive`, `/rename`, and `/later`) take effect immediately without starting an agent turn and cannot be sent with attachments; `/statistic`, `/archive`, `/pin`, `/unseen`, and `/unarchive` take no arguments.

## Open decisions

While an agent waits for your decision, a chip on every page reads "N decisions need you". On the chat page the same count sits in the chat header as a button: click it to list every open decision and open one without moving the message list. Elsewhere, click the chip to open the oldest one: the issue at the decision card, or the issue when the card has no comment. The same decision also shows in your Inbox and in the "Needs you" list. An answer with free text and no option still closes the card, and the agent reads your words.

A decision that asks you to approve a change shows the plain-language ask first. The raw change sits behind **Details**. Choose **Approve** or **Reject**, add an optional note, and press the one button below. Its label names what the send key does: **Discuss more**, **Approve with passkey** or **Confirm Reject**. Plain Enter only adds a new line. Once decided, the card collapses to a row with the state (Approved, Rejected), what happened (applied, not applied, nothing ran) and when it was asked. Click the row to open the full card.

A decision that asks you to approve a batch of changes lists every item with its own **Approve** and **Reject**. None is chosen when the card opens. The button reads "Choose N more items" and stays off until you choose every item. Then it names the result, for example "Approve 2, Reject 1 with passkey", and one passkey covers all approved items. After you send, each item shows its own effect: applied, or not applied with the reason.

### Clear your "Needs you" list

Each row in the "Needs you" list has two actions:

- **Done** marks the row handled. A decision card cannot be marked done; answer it instead.
- **Later** hides the row until a time you choose (default 2 hours, shown in ICT). A decision stays open; only its place in the list is snoozed.

**Done all** marks every row done in one step, except decisions. A message at the bottom of the screen offers **Undo** for 10 seconds.

A message you send in a DM with open questions counts as your reply to them. The agent closes each question, or it returns to you with its original age.

A message you send while a reply is in progress can still be the source of a recorded decision. If the agent confirms it read that message, the agent can quote it as the source of a decision record. If delivery is unconfirmed or failed, the message cannot be a source. The next reply lists confirmed messages the agent has not yet recorded.
