---
title: バックグラウンドエージェント
description: DM のタイトル付けなど、裏で動く小さな作業をどのエージェントが実行するかを選び、未設定のときの動作を確認します。
---

裏側で行われる作業があります。DM のタイトル付け、クイックアクションのボタン提案、長い DM の圧縮、ワークフローステップのルーティングです。これらの**バックグラウンドジョブ**は、あなたが選んだエージェントの通常のタスクとして実行されます。どのバックグラウンドジョブも、モデルを直接呼び出しません。

## ジョブ

| ジョブ | 内容 | 設定できる人 |
|---|---|---|
| `dm_title` | 最初のメッセージから DM のタイトルを付けます。 | ワークスペースの既定、または各メンバーが自分の DM 用に設定します。 |
| `quick_actions` | DM にクイックアクションのボタンを提案します。 | ワークスペースの既定、または各メンバー。 |
| `compact` | 長い DM を圧縮します。 | ワークスペースの既定、または各メンバー。 |
| `routing` | ルーティング専用のワークフローステップを担当します。 | ワークスペースの既定のみ。 |

各ジョブには**プライマリ**エージェントと、任意の**フォールバック**エージェントがあります。

## ジョブを実行するエージェント

ジョブが起動されると、Multica は最初に一致したものを選びます。

1. そのジョブについての**自分のチェーン**（プライマリエージェントを設定している場合）。
2. なければ**ワークスペースのチェーン**（プライマリエージェントがある場合）。
3. それもなければ[エージェントなしのパス](#エージェントが動かないとき)。

チェーン内ではプライマリが先に動き、次にフォールバックが動きます。未設定、対象外、アーカイブ済み、到達不能のエージェントはスキップされます。フォールバックが動くのは、プライマリの実行がプロバイダーエラーで失敗したとき、またはプライマリが[期限](#期限)を超えたときだけです。フェイルオーバーは 1 回の起動につき 1 回です。

自分のチェーンが存在するのにその全エージェントが失敗した場合、Multica はワークスペースのチェーンにはフォールバックしません。明示的な選択が尊重され、エージェントなしのパスが実行されます。

## エージェントが動かないとき

エージェントが未設定、または使える結果を返したエージェントがいない場合、ジョブごとの結果は固定です。

| ジョブ | エージェントなしの動作 |
|---|---|
| `dm_title` | 最初のメッセージから切り出したタイトル（60 文字）。モデル呼び出しなし。 |
| `quick_actions` | ボタンなし。モデル呼び出しなし。 |
| `compact` | その DM 自身のエージェントが、従来どおり圧縮します。 |
| `routing` | ワークフローステップ自身の担当エージェントが、従来どおりステップを実行します。 |

## 既存ワークスペースの移行

タイトルやボタンの生成に従来の直接モデル呼び出しを使っているワークスペースでは、直接呼び出しを取り除くビルドがデプロイされる**前に**、オーナーが `dm_title` と `quick_actions` のエージェントを設定する必要があります。設定しないと、タイトルは 60 文字の切り出しに戻り、ボタンは表示されなくなります。これは意図されたエージェントなしの動作であり、該当するワークスペースでは目に見える変更になります。

```bash
multica workspace background-agents set dm_title --agent <agent> --fallback <agent>
multica workspace background-agents set quick_actions --agent <agent>
```

## 期限

時間内に引き受けられなかったバックグラウンドタスクはキャンセルされ、実行に時間がかかりすぎたものは失敗扱いになります。どちらの場合も、ジョブは次のスロットに移ります。

| ジョブ | 引き受け期限 | 実行期限 | 期限切れ時 |
|---|---|---|---|
| `dm_title` | 10 秒 | 60 秒 | 次のスロット、その後 60 文字のタイトル。 |
| `quick_actions` | 5 秒 | 20 秒 | 次のスロット、その後ボタンなし。自動実行ではエラーを表示しません。手動の更新では従来どおり失敗を報告します。 |
| `compact` | 30 秒 | 既存の圧縮の制限 | DM 自身のエージェントが従来どおり圧縮します。 |
| `routing` | ワークフローステップのルール | ワークフローステップのルール | ワークフローステップのルール。 |

## CLI

ワークスペースの既定を表示または設定します。

```bash
multica workspace background-agents list
multica workspace background-agents set dm_title --agent haiku --fallback luna
multica workspace background-agents set quick_actions --agent none
```

自分のチェーンを表示または設定します。

```bash
multica me background-agents list
multica me background-agents set dm_title --agent haiku
multica me background-agents set dm_title --agent none   # ワークスペースの既定に戻す
```

- `<job>` は `dm_title`、`quick_actions`、`compact`、`routing` のいずれかです。`multica me` が受け付けるのは最初の 3 つだけです。
- `--agent` と `--fallback` にはエージェントの ID または名前を指定します。`none` でそのフィールドを解除します。少なくとも 1 つ指定してください。
- `list` は各ジョブのエージェント、フォールバック、**ソース**を表示します。ソースは `user`（自分のチェーン）、`workspace`、`off`（エージェントなしのパス）のいずれかです。`--output json` で同じ内容を JSON で出力します。
- ワークスペースの既定を書き込むには、オーナーまたは管理者の権限が必要です。どちらのコマンドも人間専用で、タスクトークンは固定のエラーコードで拒否されます。
