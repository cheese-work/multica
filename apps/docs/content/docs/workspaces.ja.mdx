ワークスペースは Multica の最上位の境界です。メンバー、タスク、プロジェクト、エージェント、スキル、実行履歴はすべていずれか 1 つのワークスペースに属し、別のワークスペースからは見えません。

## ワークスペースの構成

| 分類 | 内容 |
|---|---|
| **作業** | タスク、プロジェクト、コメント、添付ファイル、実行履歴 |
| **チーム** | メンバー、ロール、招待 |
| **エージェント** | エージェント設定、スキル、ランタイム、自動化 |
| **共有設定** | コンテキスト、ラベル、[カスタムプロパティ](/issues#カスタムプロパティ)、連携 |

**コンテキスト**はワークスペース内のすべてのエージェントに渡されます。チームの背景、プロダクトの約束事、長期的に有効な要件を書く場所です。一回限りの要件は、対応するタスクに書いてください。

## ワークスペースの作成

作成時に入力するのは 3 つです。

- **名前**: メンバーに表示されます。後から変更できます。
- **ワークスペース URL**: アドレスに使われる slug です。`multica.ai/my-team` の `my-team` にあたります。小文字、数字、ハイフンのみが使え、既存のワークスペースや予約済みアドレスとは重複できず、作成後は変更できません。
- **タスク接頭辞**: ワークスペース URL から自動で入力され、作成前に変更できます。接頭辞が `MUL` の場合、タスク番号は `MUL-1`、`MUL-2` と表示され、ワークスペース内で独立して増えていきます。大文字と数字のみ、最大 10 文字で、あとから設定でも変更できます。

作成者は自動的に `owner` になります。

## 設定の変更

`owner` と `admin` は名前、アイコン、説明、コンテキスト、タスク接頭辞を変更できます。`member` は閲覧のみです。

![ワークスペース設定：名前、コンテキスト、slug、タスク接頭辞と危険区域](/images/docs/workspace-settings.webp)

<Callout type="warning">
タスク接頭辞を変更すると、すべてのタスクがただちに新しい番号に切り替わります（`MUL-5` が `NEW-5` になります）。ただし、PR、ブランチ名、チャット履歴にある古い番号は更新されません。
</Callout>

### 依頼ガード

ワークスペース設定 `ask_guard_mode` は、エージェントの操作が決定リクエストを開かずに人へ作業を求めたときの動作を決めます。

| 値 | 動作 |
| --- | --- |
| `off`（既定） | ガードは何もしません。 |
| `warn` | ガードはイベントとメトリクスを記録します。操作はそのまま進みます。 |
| `block` | ガードは先にイベントを記録し、その後 `422` で操作を拒否します。復旧作業になるのは `block` のイベントだけです。 |

各イベントは作成時のモードを保持するため、`warn` から `block` に切り替えても以前のイベントは復旧作業になりません。イベントを書き込めない場合、操作は `503` と `Retry-After` ヘッダーで失敗し、何も書き込まれません。

`block` イベントを発生させた実行が終了すると、サーバーは依頼が指名するただ一人に自動復旧通知を送ります。DM メッセージ、課題コメント、受信トレイ項目を 1 つのトランザクションで書き込みます。通知は保存済みの依頼を引用し、課題へのリンクを含み、選択肢・推奨・承認を持たないため、決定リクエストにはなりません。送信されるのは、保存された元データに依頼テキストがあり、メンバーがちょうど 1 人指名され、そのメンバーがまだワークスペースにいる場合だけです。それ以外はイベントが修復待ちになります。通知のコメントスレッドで返信すると `answered` になります。ワークスペースを離れたメンバーは、通知を読むことも返信することもできません。

ガードは、エージェントが人の起動できるウェイクアップを登録する操作も対象にします。`--decision` で結び付ける、`--purpose observe` を付ける、またはエージェントだけに限定してください。[ウェイクアップ](/cli#wakeups)を参照。

### 委任されたガバナンス対象の書き込み

ワークスペース設定 `delegated_governed_writes` は、どのエージェントがガバナンス対象のフィールドに書き込めるか、また各書き込みに人の判断がなお必要かを決めます。ワークスペース設定の **委任されたガバナンス対象の書き込み** にあります。

- **編集できる人:** `owner` と `admin`。`member` は同じ表を読み取り専用で見られ、ロックの注記が表示され、編集ボタンはありません。
- **許可するエージェント:** 書き込みできるエージェント。アーカイブ済みのエージェントは追加できません。
- **許可するフィールド:** `workflow.steps`、`workflow.instructions`、`workspace.context`、`squad.instructions`、`agent.instructions`、`project.description`、`workflow.budget`、`issue.workflow` から選びます。チェックしないフィールドは、すべてのエージェントにとって読み取り専用のままです。
- **人の判断を必須にする:** 既定でオンです。オンの間、許可されたエージェントは書き込まず、判断リクエストを開きます。オフにすると許可されたエージェントが直接書き込むため、保存前に確認が求められます。

保存に失敗しても未保存の編集は保持されるので、入力した内容は失われません。

## 切り替えと退出

1 つのアカウントで複数のワークスペースに参加できます。切り替えで変わるのは表示している範囲だけで、データは移動しません。

ワークスペースを退出した後に戻るには、あらためて招待を受ける必要があります。退出すると同時に、自分が所有するランタイムは無効化され、それに紐づくエージェントはアーカイブされ、未完了の実行はキャンセルされます。

最後の `owner` は退出できません。先に別のメンバーを `owner` に昇格してください。

## ワークスペースの削除

ワークスペースを削除できるのは `owner` だけです。削除すると、その中の作業、メンバー、エージェント設定、実行履歴のすべてが完全に削除され、復元できません。しばらく参加しないだけなら、退出で十分です。
